# AutoFL Benchmark Expansion: Candidate Scripts, Dev/Holdout Split, Adversarial Set, Contamination Notes

Compiled 2026-09-22. Read-only research; nothing was downloaded or executed.
All line counts, first/last-commit dates and commit counts were obtained from the
GitHub REST API (`gh api repos/<repo>/contents/<path>` and
`repos/<repo>/commits?path=<path>`) on 2026-09-22. "First commit" is the earliest
commit touching the file **at its current path**; GitHub does not follow renames,
so where a file is known to have moved, the pre-rename date is given in the notes.
Training-loop features were determined by grep over the raw file
(`.fit(`, `GradientTape`, `def train_step`, `automatic_optimization = False`,
`.detach()` count, optimizer-constructor count, `tf.data`, download calls, DDP/AMP,
scheduler, `ignite`, `Trainer`), not by running anything.

Contents
1. Provenance of the existing 13 scripts (with three naming corrections)
2. Candidate table (92 candidates across 7 sources; 40 selected for the split, rest reserve or adversarial reference)
3. Proposed split: 20 development-frozen + 20 prospective holdout
4. Adversarial / mutant set (5 constructed + natural counterparts)
5. Contamination notes (LLM cutoffs, per-repository dates, recent files)
6. Procedural recommendations (freezing, pinning, reporting)

**Naming corrections the manuscript should make** (Section 3.6, line ~868-871):
- "MedNIST tutorial" is wrong: the file is the IXI-T1 3-D DenseNet121 sex-classification script (`densenet_training_array.py`). The true MedNIST tutorial exists only as a notebook (`2d_classification/mednist_tutorial.ipynb`, candidate M11 below). The medical-imaging criterion (iv) is still satisfied (IXI is brain MRI).
- "3-D spleen segmentation" is wrong: the file is the synthetic-data 3-D UNet script (`unet_training_dict.py`); the true spleen tutorial is `3d_segmentation/spleen_segmentation_3d.ipynb` (Task09_Spleen, candidate M12). Because this script generates its own data, it is also the one DL script that never needed the I4 fallback.
- `mnist_lite.py` is the Lightning GAN domain template; the manuscript text ("GAN") is right but the file name is not. Consider renaming the local copies (`monai/densenet3d_ixi.py`, `monai/unet3d_synthetic.py`, `lightning/gan_mnist.py`) in the expanded benchmark with a mapping table, or at least stating the real upstream paths.

## 3. Proposed split: 20 development-frozen + 20 prospective holdout

Design principle: the 13 existing scripts were necessarily inspected while the prompts and the preflight validator were written, so they **cannot** be holdout members. The frozen development set is therefore the 13 existing scripts plus 7 new ones chosen to close framework/task gaps; the 20 holdout scripts must never be opened by anyone editing prompts, exemplars, converter rules or validator stages until the prompts are tagged. Stratification targets: PyTorch 5 / Keras 5 / MONAI 3 / Lightning 3 / other DL 0-2 / non-DL 2-4 in each half; each half covers classification, segmentation, generative, sequence, regression/tabular.

## 4. Adversarial / mutant set (5 constructed + natural counterparts)

Mutants are derived from **dev-set** scripts only (so they leak nothing about holdout), are small diffs (<=15 changed lines), and each is designed so that the *plausible* conversion violates exactly one invariant while a correct conversion exists. By construction they cannot appear in any training corpus, which also makes them the strongest contamination control. Store them as `benchmarks/adversarial/<name>.py` with the diff against the parent recorded in a header comment.

| ID | Mutant (parent) | Construction | Invariant stressed | Correct behaviour expected from converter | Natural public counterparts |
|---|---|---|---|---|---|
| A1 | `mnist_detach_logging` (parent: `pytorch/mnist_main.py`) | In `train()`, accumulate `running += loss.detach()`; append `history.append(loss.detach().cpu())`; print `loss.detach().item()`; keep `loss.backward()` on the attached tensor | I3 (legitimate `.detach()` in logging must not propagate into the returned loss) | `train_step` returns the attached `loss`; logging detaches are dropped or kept on a copy | C01 `repackage_hidden` (detaches hidden state, not loss); pytorch dcgan `.detach()` on fake images; K/M notebooks with `.detach()` x2-9 (M12, brats notebook) |
| A2 | `mnist_two_optimizers` (parent: `pytorch/mnist_main.py`) | Split `Net` into `features` and `head`; create `opt_f = SGD(features.parameters())`, `opt_h = Adam(head.parameters())`, two `StepLR`s; step both per batch | I1 (which optimizer the harness owns; converter must not construct or step either inside `train_step`) | single loss returned; converter documents a merged optimizer or param groups in a build_optimizer hook if the contract allows; no `.step()` in `train_step` | pytorch dcgan (2 opt), Lightning GAN (2 opt, manual), K22/K23/K24 (2 opt in `train_step`), K05 distiller, T01 (3 optimizer branches) |

| A4 | `mnist_convnet_tfdata_missing_dir` (parent: `tensorflow/mnist_convnet.py`) | Replace in-memory arrays with `keras.utils.image_dataset_from_directory("./data/mnist_png", ...)`, then `.map(augment).cache().shuffle().batch().prefetch(AUTOTUNE)`; directory does not exist at test time | I4 (fallback must reproduce the `(image uint8 [B,28,28,1], int label)` structure of a tf.data pipeline, not a NumPy tuple) plus tf.data handling | `build_dataloader` returns a synthetic `tf.data.Dataset` (or equivalent iterator) with the same element_spec; model still trains for one step | K01, K04 (zipped pairs), K08, K09 (TextVectorization adapt), K13 (dict elements), K19 (`timeseries_dataset_from_array`), K14 (hard-coded missing path), M03/L04 (missing path, no fallback) |

### 5.4 Suggested wording for the paper (Threats to validity / Benchmark)

"All benchmark source scripts are taken verbatim from official example repositories whose files were created between 2010 and 2021 (see Table X for per-file first-commit dates), i.e. 4-10 years before the training-data cutoffs of the models evaluated (Claude Sonnet 4.6: January 2026; Gemini 2.5 Flash: January 2025; Llama 3: March 2023). We therefore assume the source scripts are present in pre-training data. Three mitigations bound the resulting threat: (i) the conversion target (the AutoFL client contract) post-dates all cutoffs and is not derivable from the source scripts; (ii) a fresh stratum of N holdout scripts first published after the Gemini cutoff, including one (`brain_tumor_segmentation.py`, 2026-02-02) published after the Sonnet 4.6 cutoff, is reported separately; (iii) five mutant scripts constructed by us cannot exist in any corpus and isolate each invariant."

## 6. Procedural recommendations

1. **Freeze the dev set before touching holdout.** Commit `benchmarks/DEV_MANIFEST.sha256` (sha256 of the 20 dev scripts, the four prompt templates, the few-shot exemplar and `preflight/`) and tag the commit (`benchmark-dev-frozen-v2`). Any later change to prompts or validator invalidates holdout results obtained after it.
2. **Fetch holdout scripts by pinned commit SHA**, not by branch: record `repo`, `path`, `commit_sha`, `fetch_date` in `benchmarks/HOLDOUT_MANIFEST.json`, and fetch with `gh api repos/<repo>/contents/<path>?ref=<sha> -H "Accept: application/vnd.github.raw"`. Do not read the files while writing prompts; have the fetch and the conversion run performed by a script, and open the files only after the conversion outputs are archived.
3. **Notebooks (M11-M14):** convert with `jupytext --to py:percent` and strip `%` magics; record the jupytext version. Prefer `.py` scripts where an equivalent exists.
4. **Multi-file scripts (C01, C04, C09, C12, C13, T01-T03, H0x):** include the sibling modules in the benchmark directory and treat the entry file as the conversion input; note in the table that these are "near single-file".
5. **Dependency gating:** K30 (medicai, kagglehub), K32 (keras_tuner), K33 (keras_rs, tensorflow_datasets), H0x (datasets, accelerate, evaluate), C13 (torchtext) need extra packages; decide before the run whether the environment includes them, and pre-register the decision.
6. **Report by stratum:** legacy-13 / new-dev-7 / holdout-20 / fresh-3 / adversarial-5 / expected-fail-2, with Wilson intervals; the manuscript's own Section 6.4 already asks for n >= 30-50 to narrow the few-shot CI.
7. **Fix the three file-name mislabels** (Section 1) in the same revision, with a mapping table; reviewers who check the upstream paths will otherwise find that "MedNIST" and "spleen" scripts are neither.
